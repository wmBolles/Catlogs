CatLogs

A local log viewer for Linux.

Your Data Stays Local

CatLogs is 100% offline. No servers, no accounts, no tracking, no analytics. Your logs never leave your computer.

CatLogs makes zero network connections. It does not phone home, send telemetry, check for updates, or transmit any data whatsoever.

All log data is read from your local filesystem and displayed locally. Nothing leaves your machine.

What CatLogs Reads

CatLogs accesses only the local files and system facilities required to display your system history:

  • Shell history files (bash, zsh, fish) from user home directories
  • System logs: /var/log/auth.log, syslog, kern.log, dpkg.log, apt logs, boot.log, daemon.log, Xorg logs
  • Systemd journal entries
  • Process information (running processes, accounting)
  • Login records (last/lastb, failed logins)
  • dmesg kernel ring buffer
  • Custom log paths you explicitly add

CatLogs only reads these files. It never modifies, deletes, or writes to system logs.

What CatLogs Does NOT Do

  • Does not connect to the internet
  • Does not send data to any server
  • Does not collect telemetry or analytics
  • Does not require an account or registration
  • Does not track usage patterns
  • Does not modify or delete any system log files
  • Does not store passwords or credentials
  • Does not run background services (except the opt-in keylogger daemon if explicitly enabled by the user)

Export Privacy

When you export to CSV, the file is saved locally to a location you choose. No data is uploaded or shared during export.

Export metadata includes: software name and version, export date and time, your local username, total record count, and which filters were active (included users, included shells, included sources, date range, search query).

You control who sees the exported file.

Key Logger Transparency

CatLogs provides full transparency for its keystroke logging feature:

  • The keylogger feature is completely opt-in
  • It is disabled by default and requires explicit user action to start
  • Key logs are stored locally only
  • You can start and stop the daemon at any time
  • The auto-start service is optional and requires explicit installation
